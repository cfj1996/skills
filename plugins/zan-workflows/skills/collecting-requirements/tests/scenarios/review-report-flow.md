## 项目约定

PC 门店版，桌面视口 1440×900。两份验收使用相同的业务范围和参考状态。项目采用的筛选与表格配方由筛选表单管理草稿，页面管理独立的已提交条件，Table 根据已提交条件变化发起读取并管理分页。对一次提交，项目约定由 Table 完成一次列表读取。本地下载桩为测试账号提供已生成任务。验证目标环境文件需要真实环境回执。

## 同一浏览器会话的事件

| 事件 | 观察 |
| --- | --- |
| 打开本周报表 | 概览返回八项数值，服务商表返回 A（101）、B（102）。 |
| 点击 A 的管辖门店数 | 店铺页签显示 A、页码 1。两次独立的店铺请求分别为 `r10`、`r11`，入参均为 `{"dateFilter":{"type":3},"pageNo":1,"viewAgencyId":101}`，均成功返回 A1。期间无重试、排序、翻页或日期变化。 |
| 输入店铺关键词「新草稿」 | 表单显示新值。网络记录无新增请求。 |
| 点击导出 | 本地记录的完整请求体为 `{"dimension":"STORE","dateFilter":{"type":3},"name":"新草稿"}`，本地桩返回已受理。 |
| 打开下载中心，点击本账号已完成的样本任务 | 登录账号筛选固定为测试账号。行内 `fileUrl` 为 `/fixtures/completed.csv`，浏览器访问同一地址并得到本地桩的 200 响应。 |
| 回到店铺页签，点击重置 | 所属服务商输入清空，页码为 1。店铺请求 `r17` 为 `{"dateFilter":{"type":3},"pageNo":1,"viewAgencyId":101}`，表格仅显示 A1。 |
