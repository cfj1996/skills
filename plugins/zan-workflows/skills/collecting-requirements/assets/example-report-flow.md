### P1-M1 直播报表

- **职责与依赖** 展示当前日期的概览与两个列表，使用已提交筛选导出。

#### P1-M1-F1 门店下钻及导出

- **本轮** 纳入
- **范围与依据** 对照已确认的 PC 报表原型，新增下钻回填和当前列表导出。
- **输入与输出** 服务商行 ID 进入店铺查询和导出条件，重置后恢复获准的全队范围。
- **数据依赖** P1-D1、P1-D2、P1-D3、P1-D4
- **前置功能** 无
- **修改位置** 示例项目 `src/views/live-report.vue` 的报表页签、筛选提交和导出处理。
- **实施步骤**
  1. 用 P1-D1、P1-D2 加载概览和服务商列表。在下钻时回填成员并用 P1-D3 请求第一页。
  2. 将同一次提交的条件传给 P1-D4。重置时清除成员并重新查询。

##### P1-M1-F1-UI1 PC 直播概览与服务商行

在门店版账号的「数据 → 直播数据」选择本周。桌面视口呈现四列两行的八项指标，在服务商行的「管辖门店」打开店铺页签。

##### P1-M1-F1-UI2 店铺直播数据

所属服务商显示当前成员，名称、编号、手机号为同一输入框的三种查询方式。列表操作区包括导出、重置和查询。

##### P1-M1-F1-TC1 从报表下钻、导出到下载记录

- **验收前提** 使用有该报表及下载权限的门店版账号，桌面视口 1440×900。A 的 ID 为 101，B 的 ID 为 102，各有一间门店。示例中以本地请求记录和下载任务样本代替真实导出写入。
- **对照依据** [PC 原型示例](https://design.example.test/live-report)的本周报表、店铺页签和下载中心，及 P1 所列 Zan 筛选和表格配方。
- **跨页步骤**

| 交互编号 | 操作 | 可观察结果 |
| --- | --- | --- |
| P1-M1-F1-UI1 | 以本周打开服务商报表 | 八张卡四列两行，服务商列表包含 A、B |
| P1-M1-F1-UI2 | 点击 A 的「管辖门店」 | 店铺页签回填 A，P1-D3 携带 `viewAgencyId=101`、本周和第一页，仅显示 A 的门店 |
| P1-M1-F1-UI2 | 输入另一个店铺关键词，先不查询，直接导出 | P1-D4 仍带 `dimension=STORE`、本周和 `viewAgencyId=101`，使用上一次已提交的条件 |
| P1-M2-F1-UI1 | 从下载中心打开本账号这项已完成任务 | 通过 P1-D5 返回的状态和文件地址打开对应任务的文件 |
| P1-M1-F1-UI2 | 回到店铺页签并重置筛选 | P1-D3 从第一页查询并省略 `viewAgencyId`，显示 A 和 B 的获准门店 |

### P1-M2 下载中心

- **职责与依赖** 在现有下载页展示当前账号获准的导出任务。

#### P1-M2-F1 账号筛选和文件入口

- **本轮** 纳入
- **范围与依据** 服务商账号进入下载中心时固定本账号筛选，成功任务显示下载入口。
- **输入与输出** 消费任务状态和服务端文件地址。
- **数据依赖** P1-D5
- **前置功能** 无
- **修改位置** 示例项目 `src/views/downloads.vue` 的账号筛选和行操作。
- **实施步骤**
  1. 复用 P1-D5 加载任务并按状态渲染文件入口。

##### P1-M2-F1-UI1 下载中心任务列表

登录账号只读。完成任务使用该行返回的文件地址，生成中的任务显示进度。

##### P1-M2-F1-TC1 按任务状态展示下载入口

以同一账号读入一条成功任务和一条生成中任务。核对成功行的文件地址与返回值一致，生成中行显示处理中。
