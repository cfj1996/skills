# 需求任务关联

用本轮选定的 TAPD Task 串起责任范围、Plan、验证和交付事实。关联来自已有
任务、分支、Plan 和能力返回结果，不建立新台账或运行时模型，不把 Task
变成另一份重复需求文档。

## 关联范围与事实来源

| 关联 | 使用已有事实 | 展示时点 |
| --- | --- | --- |
| 父需求与所选任务 | Story/Task 读回及父子关系；任务标题、负责人、最终预估工时 | 现有任务可用真实链接；拟创建任务只展示稳定 key 和提案，准确读回后才补 ID/链接 |
| 项目与开发分支 | Task 的 project/deliveryUnitKey 与已确认仓库、固定分支 | 清单确认时绑定；多个 Task 可共用分支，不按 Task 重复创建分支 |
| 交付范围与方案 | scope/exclusions/featureRefs/acceptance 和模块 Plan | 已有 Plan 链接实际位置；新 Plan 先预览、获准保存读回后再链接 |
| 步骤与接口 | tapdTaskKey、T-* 步骤及 F-*/API-*/DEP-*/E-* 引用 | 仅关联当前 Task 真正涉及的模块、接口、依赖与证据，不为未改动接口制造任务 |
| 待决事项 | 模块问题、implementationPlan.blockers、ISSUE-* 及依赖事实 | 明确影响哪些所选 Task/步骤/验收，保留缺口、影响、责任方、补齐条件及阻塞范围 |
| 验证与评审 | 当前 diff、实际命令/场景结果、AC-*、E-*、RR-* 和 ReviewedChange | 实际完成后按证据覆盖范围归属；计划与已运行结果分别表述 |
| 代码与测试交付 | 当前轮真实提交/MR、Jenkins 本次构建、共享 Wiki 与 TestSubmissionResult | 对应交付获准执行并读回后才关联，不预造未来链接 |

稳定任务 key 与真实 Task ID 通过现有 `TaskBreakdownResult.records` 对应；
正式 Plan 继续使用 `taskBreakdown` 和每步 `tapdTaskKey`。不新增
`taskBindings`、状态 schema、JSON 台账或 Task 专属文件。

## 任务表与清单中的呈现

继续使用 [确定与执行清单规范](../../../references/execution-checklist.md)，不增加
Task 列，也不为每个 Task 重印项目、分支和整份方案。

- 概览给父需求及本轮选定范围，可只写任务数量。`### TAPD 任务` 放在
  `### 执行内容` 前，即使只有一个已有 Task 也使用三列：

  | 序号 | 标题 | 工时 |
  | --- | --- | --- |
  | #F01 | 〈Task 标题及准确链接〉 | 〈最终预估工时，小时〉 |
  | #F02 | 〈Task 标题及准确链接〉 | 〈最终预估工时，小时〉 |

  序号全清单跨项目唯一，确认前后保留；新增追加，删除不复用，修改顺序不
  重编号。标题有真实读回才加链接；拟创建只显示拟创建标题，不伪造身份。
- 交付范围汇总该项目本轮 Task 的交付和排除项；实施方案和验收摘要连接
  相应任务的 Plan/步骤/场景。后续直接引用 `#F01` 等阅读序号，待决事项也
  用其定位受影响任务，不只写“后端未好”，不重印长标题或 URL。
- `#F01` 仅是 Task 的阅读索引，`#01` 才是详情备注；两者都不是 TAPD ID、
  `tapdTaskKey`、Plan 步骤或 `F-001` 功能标识。不增加 JSON 映射/台账，
  真正交接继续绑定原 ID/key/records，旧 Plan 不为阅读索引改写真实身份。
  同一 Task 在多处引用只列一次、工时只计一次，每处仍符合其实际项目/范围。
- 备注只展开必要的范围、方案、依赖或验收，不在 `#01` 下再放旧多列 Task
  明细表。实际创建/更新仍在“需求写入事项”按 `#F01` 展示负责人、本轮动作、
  完整拟写字段及旧/新差异，结合任务表/主表/Plan 共同绑定确认，不能只报序号。
- 工时是最终预估工时，按已核实单位展示，不展示内部系数、算法或实际耗时。
  已有任务未填写就写“未填写”，未核实写“待核实”；只读复用不为排版补估时。
  正式 Task/Plan 就绪仍须满足其人员、估时及准确读回门禁，不能以展示占位绕过。
- 小需求只有 Story、没有 Task 时，仍用 Story＋简短执行说明，不强制
  拆任务、估时或生成 Plan。已选 Task 的小改动保留真实父需求、人员与
  本轮范围，不为展示关联构造正式 TaskBreakdown 或伪造任务就绪结果。
- 输入是一个 Task 时只实施该 Task 的已选范围；同 Story/Plan 的兄弟任务
  不是默认开发范围。可引用外部任务作为依赖，但引用不授予修改权限。

## 准备、实施与交付

1. **准备**：读取真实 Task 与父需求，复用现有拆分/读回结果，核对本轮
   所选 key/ID、责任范围和项目。创建/更新仍走原完整预览与确认；不把
   已有任务当成缺失重新创建，不为补关联重写 REUSE 的历史描述。
2. **编写 Plan**：复用模块 Plan 的任务关联表、步骤、接口和验收引用。
   一个 Plan 可含多个 Task，一个 Task 可含多个步骤；工时只按 Task 计算
   一次。系统 ID 按已确认映射和准确读回补齐，仍遵守原 Plan 保存门禁。
3. **实施**：按所选任务依赖执行，每步知道属于哪个 Task、改变哪项行为、
   对应哪个验收。范围/人员/工时实质变化先展示差异；外部缺口明确阻塞
   哪部分，不把等待接口算开发投入，也不扩大到其他人的任务。
   [多任务实施](../../implementing-work/references/parallel-execution.md) 可把独立
   步骤分给子代理，但不机械地按 Task 数量派发。子代理分工是代码修改归属，
   不替代 TAPD 中的人类负责人或改变工时；依赖、路径与验证沿用同一 Plan/brief。
4. **验证与评审**：将实际结果关联到被覆盖的 Task/步骤/验收。项目 lint
   通过不等于所有 Task 验收通过；仅依据明确覆盖关系报告任务内行为已验证。
   共享证据引用一次即可，不按 Task 重跑相同命令或重复计时。一个项目的
   完整 diff 可一次评审覆盖多个所选 Task，不强制每个 Task 单派评审 Agent。
   跨任务联调未完成时保留缺口，不能报整个需求已完成。
5. **交付**：用户选择交付后复用真实提交、MR、测试构建和 Wiki 返回结果，
   说明覆盖哪些本轮任务与源码版本。一个 MR/构建可关联多个 Task，共享
   分支或 MR 不自动证明其全部任务已验收；旧结果需核对当前范围/版本。
   一个需求仍共用 Wiki，不按 Task 新建；仅处理实际交付任务的已授权
   链接和登记，不扩大到全部兄弟任务。

只做开发时报告代码、验证、评审和遗留事实，不要求先有提交、MR、构建
或 Wiki 链接。初始任务提案、未保存 Plan 和未来构建不能伪装成现有产物。

## 进度与收尾

普通进度只说“正在处理哪个任务、完成了什么、还缺什么、下一步是什么”。
多任务收尾或交接时，按所选 Task 汇总本轮结果：

| 任务 | 本轮完成范围 | 验证/评审依据 | 遗留及后续 |
| --- | --- | --- | --- |
| `<真实 Task 链接与名称>` | `<实际完成的行为/步骤>` | `<已执行结果及对应 Plan/验收；未覆盖项保留>` | `<具体缺口和下一步；已实际交付时可附本轮 MR/构建/Wiki>` |

这是既有 Plan/执行结果的摘要，不另存任务进度台账。代码进度、验证结果
与 TAPD 实际状态分别说明；单步完成、代码已评审、MR 已合并均不自动意味
着 TAPD Task 已 done。仅实施选定范围时也不能宣称整条 Story 完成。

## 写入边界

关联不授予 Task 状态、评论、描述、预计/实际工时、日期或其他字段的写权限。
这些变更仍走原请求、预览、确认与精确读回；Plan 维护也沿用原授权。
REUSE 只是读取和引用，不能为了关联完整自动改旧任务或刷评论。

本地 Plan 路径只用于本机可访问的清单/会话，不当作团队可访问的 TAPD
共享链接回写。回写共享链接前核实真实可访问地址并取得对应写入授权。
未产生、未核实或不可访问的关联如实说明，不生成占位链接。
