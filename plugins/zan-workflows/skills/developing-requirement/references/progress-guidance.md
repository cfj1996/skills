# 进度与下一步

普通更新说明当前所选任务/范围、已完成行为、验证结果、真实缺口和下一步。
只列本轮实际经过的阶段；不每次重印全流程、内部状态枚举或固定操作菜单。
执行确认仍使用 [六列清单](../../../references/execution-checklist.md)，不能用
进度表或任务完成摘要代替。

## 当前结果决定下一步

- 尚有需求问题：展示所缺业务规则或闭环与补齐条件，先完善范围。
- 范围明确但实施条件不足：展示接口/字段、环境/权限等缺口及影响；补齐后
  才开始受阻实施。用户只要计划时可保存阶段 Plan，明确其不可实施部分。
- 等待清单授权：只问一次是否执行；等待回答不算待决事项。
- 任务写入部分成功或结果不明：先准确读回原任务，显示已成功 ID 与剩余差异，
  不重复创建。不因成功项存在就跳过 TASKS_READY 门禁。
- 实施、必需验证或独立评审未通过：推荐先解决当前阻塞，不能推荐提交测试。
- 本轮实施与评审完成：报告完成范围与证据。若用户未要求交付，到此结束；
  执行清单已覆盖提测时核对准确计划后直接推进，不再问是否继续；未覆盖时
  推荐不构成授权，新增交付或独立技能仍先确认具体计划。
- 等待人工合并：展示准确 MR 和 userAction.message，说明需联系有权限人员；
  人工合并后核查同一 MR，再继续尚未完成的已授权操作。
- 用户暂停/停止：保留真实已完成效果；只有明确恢复才继续，不重复外部写入。

## 任务、项目与终点

遵循 [任务关联](task-linked-delivery.md)。任务结果只覆盖实际选择的范围、
Plan 步骤和验收，项目 lint 或共享 MR 不证明全部 Task 完成。TAPD 实际状态
与代码进度分开，不自动标 done。多任务/多项目交接才展开结果表，注明共享
证据及每项未覆盖内容；整体不能越过最早的必需阻塞。

BRANCH_ONLY 在准确分支读回后结束；PLAN_ONLY 在获准保存读回后结束，
未就绪的阶段 Plan 不能推荐立即实施。IMPLEMENT 在全部相关项目 REVIEWED
后结束；SUBMIT/GO_LIVE 由对应能力的准确结果决定，不能把待人工处理算成功。

合并/上线的清理检查和确认由 going-live 负责。只有有安全候选才展示精确
资源清单；无候选或检查受阻如实说明，用户选择保留后不反复询问。
主流程只将未授权的清理列为下一步建议，不例行追加清理确认；独立 CLEANUP
请求仍按精确资源清单确认。已授权操作未完成时先继续，不把它们改成用户待办。
后续请求继续时核查原范围、分支和已有结果，复用仍有效授权与证据，只补
受影响的差异。下一步一句话能说明时，不另造状态模型或恢复文档。
