# 修复记录与提测执行演练

使用当前 `fixing-bug`、`implementing-work`、`submitting-for-test` 及各自引用的
记录、交接和评审规则，独立处理以下模拟输入。每案独立，不承接其他案例状态。
所有 ID、代码问题、回执和评论均为模拟事实；不调用外部 API，不创建分支、不改源码或文件。

逐案返回：当前是否可继续、下一步操作及其顺序、到指定终点会创建哪些评论、
哪些事实必须读回，以及失败时保留什么/在哪停止。给出所依规则的文件和段落。
不要为了填补缺口假造评论、部署或评审结果。

## A. 代码评审通过后的提测前返工

- 用户已确认一个 Bug 的完整修复和直接提测清单，单仓库、原固定分支，STANDARD/DEPLOY。
- 状态/处理人写入已核实，全部实施验证和首次代码独立评审已通过。
- 拟写修复记录覆盖该次代码与验证；当前没有本轮修复评论。
- 准备完整提测计划时，独立评审确认组件无扩展名导入实际解析为同名辅助脚本，评审不通过。
- Git 尚未提交/推送，Jenkins 尚未触发，Wiki 尚未写入。
- 后续修正明确导入扩展名，并补齐受影响验证、独立评审和当前草稿；范围及原授权不变。

分别说明发现问题当下，以及后续全部交付门禁顺利通过时的操作。

## B. Wiki 已核实，链接尚未写入

- 一个 Bug 的代码/记录草稿和完整提测计划均已评审、确认。
- 所有必要仓库 Git 包含关系通过，所选构建有准确 BUILD_SUBMITTED 回执。
- Wiki 正文已创建并准确读回，当前 Bug 评论中没有该 Wiki 链接，也没有修复记录。
- 队列仍在等待，当前没有构建结果。

说明从当前点到登记待测试的评论、读回与状态操作顺序。

## C. 最终记录读回中断后的续接

- 所有必要 Git、构建接受、Wiki 和独立链接评论均已通过，准确回执仍有效。
- 本轮修复记录创建返回准确评论 ID，但随后读取超时；状态尚未登记。
- 现在收到用户继续指令，只读查询显示该 ID 的 Bug、作者、完整正文和排版全部正确。
- 当前源码/差异、验证与评审绑定未变化。

分别说明读取超时时和续接读回成功后的下一步，列出会重放的操作。

## D. 仅修复终点

- 用户明确只修复验证，不提测；本轮范围和单条记录操作已确认。
- 一个 Bug 的全部必要仓库、跨仓库验收和独立评审均通过，草稿符合最终事实。
- 当前没有本轮修复记录；Wiki/Jenkins 未查询，Git 未提交。

说明实施能力如何结束本轮，以及哪些交付能力会被调用。

## E. 已结束实施的相同代码后来提测

- 用户上一轮明确仅实施，全部验证/评审及最终修复记录准确读回后结束。
- 本次用户请求直接提测，源码、验证事实和完整修复范围未变化。
- 当前记录完整覆盖这些事实，本次准确提测计划已确认。
- STANDARD/DEPLOY 的所有交付和 Wiki/独立链接门禁后续均顺利通过。

说明本次是否需要创建修复评论，以及最终登记需要的证据。

## F. NO_WIKI / SKIP

- 用户确认直接提测，不写 Wiki、不构建。
- 单仓库 Bug 的完整代码/草稿评审和测试目标包含关系均通过。
- 没有本轮修复记录，准确评论账号及正文操作已授权。

说明剩余操作及会使用的服务，不假定 NO_WIKI 免除其他 Bug 操作。

## G. 必要仓库尚未全部通过

- 一个 Bug 的同一确认范围包含两个必要仓库，均绑定原分支。
- 第一仓库代码/验证/评审通过，第二仓库必要验收失败，跨仓验收未通过。
- 第一仓库有局部草稿，第二仓库尚不能证明修复完成。

说明可交接的结果、评论操作及是否可按首仓库进入正式提测。

## H. 已发表记录与本轮事实不符

- 已确认这是同一轮修复，没有新的修复范围或新一轮授权依据。
- 本轮评论已经发表，但当前已评审事实与其中一项修复说明冲突。
- 可用 TAPD 工具只有评论读取和创建，没有评论编辑能力。
- 其他交付前置均已满足，状态尚未登记。

说明下一步及可以创建的评论，不能假设存在未提供的编辑接口。

## I. Story 的正式提测

- 一个 Story 的所选 Task 范围、代码评审和计划均通过，并取得完整交付授权。
- STANDARD/DEPLOY 的 Git、构建接受及 Wiki/回链门禁全部通过。
- 显式版本登记政策满足；没有 Bug 实体或 Bug 记录草稿。

说明剩余写入及是否缺少修复记录。
