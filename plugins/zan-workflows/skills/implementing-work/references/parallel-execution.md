# 多任务实施

主代理持有 `implementing-work` 的完整授权、分支和结果；开发子代理只处理
分配的实现步骤。使用宿主原生子代理能力，不另建用户聊天，不把整个入口或
`implementing-work` 再交给每个子代理。没有子代理能力时，按相同边界串行完成。

## 选择与拆分

- 小改动由主代理直接完成；同类小步骤可合成一个工作包，不按 TAPD Task
  数量机械创建子代理。步骤沿用真实 Task key/Plan 编号，没有则用行为名称。
- 先检查行为、接口与数据依赖，再检查文件和共享资源。不同文件不自动表示
  独立；公共接口、类型、依赖配置或生成规则先由唯一负责人完成并验证。
- 只有前置依赖已验证、接口约定明确、写入范围和资源不冲突的步骤才同时启动。
  跨仓库满足这些条件也可并行；同一文件的不同代码段仍按一个写入范围串行。
- 默认最多同时运行 2 个开发子代理，确有独立工作时可到 3 个；跨仓库合计，
  不让子代理递归派生。宿主容量、用户限制或可用资源更低时降低并发。

已有 Plan 在原步骤内记录前置步骤、修改路径/唯一负责人、共享契约、验证和
可并行批次，沿用现有文本与依赖字段，不增加模型字段或第二份进度台账。
没有 Plan 时在 `implementationBrief.steps` 的说明中保留同样适用的事实；
采用子代理本身不要求创建 Plan、TAPD Task 或重算工时。
确定清单的实施方案可以简述“接口先行，前后端并行，最后联调”，长内容仍
用原编号备注。范围/分支/实际写入没变时，派发和批次调整不新增用户确认。

## 派发前

1. 主代理先完成每个参与项目的准备、授权和固定分支核验；同仓库只执行一次
   分支操作。Bug 还须完成共享状态/处理人和开始评论读回，才可派发源码任务。
   不同分支共享同一检出目录时不得并发；不为并行创建临时分支或工作树。
2. 以真实仓库路径规范化允许修改的文件/目录，排除别名和嵌套目录的重复归属。
   每个文件只交一个当前写入者，包括主代理；公共文件或范围不清时先串行。
   检查生成文件、锁文件、构建输出、测试数据库、端口和浏览器会话等资源。
   不能隔离的测试/构建串行运行，不能只检查业务源码是否重叠。
3. 保留每个仓库的 HEAD、当前差异及原有未提交改动基线，核对所有任务的
   修改范围都在授权中。分派的子代理只能认领自己相对派发基线的变化，不能
   把同分支上其他任务的 diff 当成自己的实现或测试证据。
4. 用 [开发子代理](../agents/task-implementer.md) 派发最小充分上下文：
   任务/步骤、准确仓库与分支、相关规则、需求/接口与前置结果、允许和禁止的
   修改路径、局部验证、资源约束以及完成条件。支持时使用独立上下文；不复制
   整段会话，也不要求子代理重新路由项目、查 TAPD 或重新规划全部需求。

## 主代理与子代理的边界

| 操作 | 负责者 |
| --- | --- |
| 范围决定、任务依赖、文件归属、工作包派发与回收 | 主代理 |
| 固定分支创建/切换、远端 refs 刷新、Git 索引、依赖安装与公共环境配置 | 主代理，受原阶段授权限制 |
| 分配范围内的源码/测试修改、不会争用资源的局部验证 | 对应开发者 |
| TAPD、Bug 评论、Wiki、提交、推送、MR、Jenkins | 主代理在原技能阶段处理；并行不增加授权 |
| 集成验证、最终差异核对和安排独立评审 | 主代理 |

子代理遇到需要修改别人的文件、公共契约或依赖安装时，先报告所需改动与
影响，保持当前范围；不能自行扩大、改分支或回退他人工作。主代理先核对实际
影响，再安排唯一写入者；涉及需求、分支或外部写入的实质变化沿原规则确认。
子代理不派生代理、不自动运行评审/提交/收尾技能；任务返回不代表 TAPD 已完成。

## 按依赖推进与恢复

- 独立就绪任务可同批开始。主代理核对先完成任务的实际 diff、局部验证和
  接口输出后，才解锁其下游；子代理的一句“完成”不能解除依赖。
- 一个任务受阻时暂停其下游，保留已完成效果。只有能证实仍独立且资源安全的
  已授权任务可继续；范围、分支或共享契约失效时暂停所有受影响写入。
- 调整写入归属、处理公共文件、切换分支或最终集成前，先停止并确认相关
  子代理及其写入命令已结束，再重新读差异。发出中断、超时或失联不证明
  写入已经停止；状态不明时保留范围占用，不派新代理并发重做。
- 续接先核实在运行的子代理、现有差异和验证有效性，保留当前会话中的关联；
  只接着完成缺失或失效步骤。已落盘但未报告的改动先审查，不盲目重发任务。
  不写运行 ledger、子代理报告文件或恢复状态文件；既有 Plan 更新仍走其授权。

## 验证与交接

子代理返回任务归属、实际修改路径/行为、检查命令及结果/局限、已知问题和
所需下游输入。主代理逐项核对实际文件，确认无越界和遗漏，再汇总各任务的
验证覆盖；共用检查只运行/引用一次，不能把某任务局部通过推成全项目通过。

在相关写入全部停止、diff 稳定后，执行必要的项目检查与跨任务/跨仓库联调，
再给独立 reviewer 当前完整 diff、各任务归属及验证。主代理安排评审，开发
子代理的自检不替代它；无需每个小任务都额外派一位 reviewer。可以在稳定的
独立仓库间并行只读审查，仍须汇总接口一致性和跨仓库验收。
修复评审问题只重验受影响部分，但最终交接必须覆盖实际整轮差异。

复用 `ReviewedChange` 的 Change/Verification/Review 内容记录归属，不新增
终态、任务 ID 或结果 schema。所有必要任务/仓库和整体评审通过后才返回
`REVIEWED`；Bug 还须统一完成记录读回。部分完成只报告实际进度和缺口。
