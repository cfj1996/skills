# 需求与实施就绪检查

## 三个独立判断

需求确认回答业务行为是否明确；依赖就绪回答某一步的条件是否齐备；执行授权
回答本轮允许哪些操作。Plan 保存状态另行记录，不能代替上述任一判断。
本检查适用于正式 Plan 与简短 `implementationBrief`，不为小任务创建模型或文件。

业务问题汇总到六列主表“需求待确认”；外部事实与缺口按
[外部数据与依赖](../../../references/external-data-dependencies.md)单列；内部组件、
代码落点、数据所有权和技术决策放实施依据。沿用
[完整清单](../../../references/execution-checklist.md)，不再把接口或 Key 缺口塞进业务问题。

## 适用检查

1. **业务范围与闭环**：页面/模块职责、包含/排除项、触发、规则、角色行为、
   正常/异常结果、恢复与必要后续动作。
2. **业务输入输出**：展示/提交哪些信息、字段业务含义、业务枚举语义、默认
   行为、跨页面联动及可观察验收。字段名、传输类型和编码属于外部契约。
3. **交互与验收**：初始、加载、空态、错误、禁用、成功、重复提交、刷新回显；
   关键场景的验证入口、预期及 Mock/静态检查/真实联调各自能证明的范围。
4. **外部数据与依赖**：需要新增/改变真实消费时先查项目实际正式来源，记录
   API method/URL、参数/响应字段、类型、传输枚举、错误/状态码及安全事实；
   再核实适用环境、账号权限、凭据配置引用、服务及测试条件。复用已知来源，
   一个权威来源足够时停止，不为了模板完整遍历所有系统。
5. **内部实施依据**：项目组件体系、路由/参数、状态和数据归属、复用边界、
   当前代码落点及真实验证命令。Agent 先自行查证，不能交给用户猜实现事实。
6. **本轮阶段与授权**：整体需求与本轮执行步骤分开；保留未来步骤的未就绪
   事实。明确 UI/Mock、编码、真实联调、验收、测试交付或生产分别需要哪些条件。

纯 UI/已批准 Mock 不隐含后端实现或未请求的真实联调。使用
[跨项目 Mock 规范](../../../references/mock-development.md)选择数据入口替换或契约
HTTP Mock；未确认 method/URL/Schema 时不生成虚构接口或 Draft。

## 缺口判定与解除

- `REQUIREMENT_BLOCKER`：业务范围、规则、字段业务语义、角色行为、结果反馈
  或验收存在缺失/冲突。未解决前不能确认受影响需求；只进入“需求待确认”。
- `IMPLEMENTATION_BLOCKER`：业务已经明确，但当前步骤所需外部依赖或内部
  实施依据不足。允许保留需求已确认；在外部依赖记录或内部实施 blockers
  说明缺口、影响、责任方、可核验解除条件和受阻步骤/验收。
- `NON_BLOCKING`：已有依据表明当前阶段不受影响。`none/not-applicable` 必须
  说明证据，不能通过删除问题、改成不适用或选择 ui-mock 清空真实阻塞。

业务字段含义或权限行为不明，即使问题由接口暴露，仍是业务阻塞；只缺传输
字段名/类型、配置或环境时不得把需求结论改成未确认。“未查到/权限不足/读取
失败”仅说明尚未核实，不证明接口不存在或 Key 未配置。Key/token 实际值不得
进入对话、Plan、评论或面板；只记配置项、保管位置引用、环境和访问验证状态。

对外部依赖逐阶段判定：

- 缺少正式契约可能阻塞真实接入，不一定阻塞明确获准的功能数据 Mock。
- 契约已确认但服务/账号未就绪，可允许不依赖运行环境的编码，保留真实联调
  和验收阻塞；不得悄悄减少必需验证。
- 一项依赖影响多个页面时记录一次并关联全部消费点；其他独立、已授权步骤
  可以继续。全部选定交付完成前不能宣称整条需求完成。

解除必须有对应的新证据或业务决定，记录状态变化及受影响步骤；建议、处理
计划、配置项存在或用户执行确认都不证明真实依赖已就绪。外部事实补齐保留
未改变的业务结论，刷新失效实施依据、验证和独立评审；有实质业务/关键方案/
人员工时或交付范围变化才按原规则重新展示完整清单并补充确认。

## 实施与交付门禁

只有 `requirement_blocker_count=0` 才能确认需求范围。实施还要求本轮已选定
步骤必需的 `implementation_blocker_count=0`、依赖审查有证据且其余门禁通过。
正式模型按 `executionScope` 核对当前阶段/所选功能和 Task，未来依赖继续留在
同一 Plan；不能将整个需求误标为全部就绪。旧模型缺依赖审查信息只能读取/
评审，补齐明确审查后才可实施。brief 同样按实际阶段检查，不绕过正式约定。

含 Mock 的 ui-mock 阶段必须有匹配、明确批准的 `MOCK_ONLY` 范围、实现位置、
场景、真实调用边界、验证局限和退出条件；仅填写阶段名不足以放行。默认仅
本地执行。进入测试分支/测试环境及 Wiki/登记前必须清查准确源码范围，展示
Mock 测试交付清单并取得明确人类确认；普通开发/直接提测默认授权不覆盖它。
生产禁止将 Mock 模块及其数据、handler、runtime、启用入口带入制品或业务
运行链路，需源码退出和本次构建绑定的制品/流水线门禁，不能用开关关闭替代。

Task 估算复用上述责任、源码基准、已有能力、新增/适配/验证证据；不按页面数
补工时，不把等待接口算开发投入，不因依赖状态更新自动改 Task 工时/状态/日期。
