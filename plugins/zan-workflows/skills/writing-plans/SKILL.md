# 页面原型评审

Default model profile: `BALANCED`。见[模型路由](../../references/model-routing.md)。保留已有的显式原型评审入口。要收集新的 Story、Bug 或生成执行文档，进入[需求收集](../collecting-requirements/SKILL.md)。

## 评审模式选择

从用户的页面、PRD、原型和已有计划提取模块输入输出、交互和验收。按[页面评审规范](references/page-review-standard.md)同时列出现有证据和缺口。接口消费按[契约阶段](references/api-contract-stages.md)核对。需要解释旧文档状态时查[状态模型](references/status-model.md)。同一页面有多个功能时逐项核对。

普通评审在会话中展示。用户选择交互面板时，按[功能评审运行协议](references/feature-review-runtime.md)在当前原型收集意见。范围评审只用会话级的候选状态，允许在缺少工作项或仓库产物目录时评审。读回实际提交和用户意见后，将其交回需求收集。正式保存由该技能执行 TAPD Wiki 的预览、确认和读回。

原型评审只读消费项目及已有资料。新的执行步骤以工作项和功能编号组织，收集的输出为会话稿或一份 TAPD Plan。业务仓库的文件、项目目录规则与 TAPD Task 都不作为输出。
