# 本地验证范围与资源预算

适用于开发、修复、人工改动后的补验和本地冲突验证；Jenkins 的构建/发布继续
遵守原交付规则。目标是取得本轮行为的充分证据，避免机械串联全仓 lint、类型检查
和 build。主代理选择命令并统一安排重任务，开发子代理只做分配的局部检查。

## 先选范围，再启动命令

1. 核实项目运行时、package scripts、工具配置及命令最终展开的范围；名为
   `lint`/`typecheck` 的脚本也可能递归整个 monorepo。不要为了探测耗时先跑一遍。
2. 从变更文件、所属包/应用和实际消费者选最小充分检查：行为复现/相关测试优先，
   lint 传准确文件或目录；使用已有包过滤、受影响测试和项目原生增量缓存。
   不使用 watch，不顺手 `--fix`，不清缓存、不重装依赖来“保险验证”。
3. 类型检查保留原 tsconfig、框架插件和项目引用边界；有原生包级入口则使用。
   禁止临时生成只含几个文件的 tsconfig，或用 `tsc file.ts` 冒充项目类型通过。
   没有有效局部入口时，先判断全量类型检查对当前改动是否必要；不自动升级全仓。
4. build 只在产物、打包配置/导出、依赖、编译转换或运行时集成等风险需要时执行，
   优先实际受影响的应用/包。普通页面/逻辑修改不因为“开发完成”自动全量构建。
   共享接口变更应覆盖实际受影响消费者，不能只靠 diff 小就省略必要回归。
5. 只有用户明确要求、项目硬性规则或具体风险无法被局部证据覆盖时才升级全量。
   说明触发原因；硬性必检不能静默跳过。若本机预算内无法完成，优先复用绑定当前
   版本、范围、命令和环境的已完成 CI 结果；尚未完成的 Jenkins 队列回执不算通过。
   需要新触发 CI 时沿用原授权，不能因本地优化自动部署或发布。

已有验证仅在源码/相关依赖配置、命令和环境仍适用时复用；稳定 diff 上共用检查
执行一次。后续修改仅补失效部分，不在评审、提测、每个 Task 中反复跑同一全量命令。

## 限制本机开销

- 同机重型 lint/类型检查/测试/build 串行，跨仓库、主/子代理合计同时最多一个。
  实施可以并行，重检查交主代理排队；不要用 `Promise.all` 同时启动这几类命令。
- 工具原生支持时限制 worker 为 1–2，并复用增量缓存。先检查真实参数，禁止
  盲传 `--max-workers` 等未知选项。不要通过扩大 Node 堆、关闭限制或无限重试解决 OOM。
- 默认单命令预算：lint/相关测试 120 秒、类型检查 180 秒、build 300 秒，
  进程组 RSS 合计 2048 MiB。这是初始上限，不是必须等满的时间；已知资源紧张时
  下调。明确的项目预算可替换默认值；不得自动加码、取消上限后原样重跑。
- 使用 [执行器](../scripts/run-local-check.mjs) 运行可能较重的本地检查，
  传入项目实际运行时和原生命令；执行器自己的 Node 不替代目标项目 Node。
  这不是工具调用的等待超时：执行器会在超时/超限/收到取消或输出通道故障时，先 TERM 再 KILL
  本次命令的整个进程组，并读回进程退出情况。失败或清理不明不启动后继重任务。
  执行器同时降低命令的 CPU 调度优先级；这不是 CPU 使用率硬上限，工具内部
  worker 数仍按上条约束配置。

```bash
node "$PLUGIN_ROOT/scripts/run-local-check.mjs" \
  --kind lint --cwd /absolute/project -- \
  pnpm exec eslint src/changed-file.ts
```

`--kind` 为 `lint|type|test|build`；按已确定预算可传 `--timeout-seconds N`、
`--max-rss-mb N`。参数通过 argv 传递，无隐式 shell；一个检查一个命令。
输出只有结果和有界日志尾部，长任务每 30 秒提供进度；不创建工作流报告文件。
执行器支持 macOS/Linux，RSS 为定期采样而非操作系统硬隔离，瞬时峰值可能超过
预算；它不能约束主动脱离进程组的 daemon。不要启动后台/watch 任务做验证。
其他平台或无法采集内存时先报告限制，使用已具备等效进程树取消/预算能力的执行方式，
不能无保护降级到全量命令。

## 中断后与验收

超时、内存超限、监控失败、命令失败、输出通道故障或取消都不是通过。说明已覆盖范围、实际
结果、停止原因和未验证项；先缩小范围/修正具体问题，再决定是否补验。
不在同一条件下自动重跑，不杀同机其他开发进程。必要检查未完成时保留原阻塞，
不能只靠局部 lint 或代码评审宣布整体验收通过；非必要全量检查未运行则说明范围，
不制造额外阻塞。已有可信行为证据与未执行的全量检查分开报告。
